# Radius Guard EC2 1.2

**GitHub Pages＋既存Entry SystemのEC2で運用する場合は、先に DEPLOY_EC2_JA.md を読んでください。以下は機能説明とローカル実行手順です。**

Discordサーバー荒らし対策Botと、白黒の管理画面を一緒に動かすシステムです。
Windows・Linuxで起動でき、1つのBotで複数サーバーを管理できます。Botトークンは手元で入力します。チャットに送信する必要はありません。

## できること

| 対策 | 初期設定・動作 |
| --- | --- |
| 連投 | 同じ人が8秒で6回投稿・編集 → 10分タイムアウト、直近60秒のキャッシュ済み投稿を最大30件削除 |
| 大量メンション | 1投稿でユーザー・ロールの種類数が合計8以上 → 削除・タイムアウト。実際の@everyone/@hereメンションは1回で対象 |
| 大量入室 | 15秒に10人 → その時間帯の入室者をタイムアウト。その後10分間の新規入室者にも適用 |
| 管理操作荒らし | 同じ実行者が15秒に合計3回、チャンネル削除・ロール削除・BAN・キック・危険な権限付与 → 操作可能な危険ロールを外し、タイムアウトを試行 |
| 権限付与の取消 | 閾値到達時に、直近の監視時間内で同じ人が追加した危険権限・危険ロール付与を可能な範囲で取り消す |
| Bot追加禁止 | 初期OFF。ONで所有者以外が追加したBotをキックし、追加した人を封じ込める |
| Webhook作成禁止 | 初期OFF。ONで所有者以外が作成したWebhookを削除し、作成した人を封じ込める |
| 緊急ロック | 現在ある対応チャンネルの投稿・スレッド作成・リアクション・VC接続を権限上書きで制限。解除時は保存した値に戻す |
| バックアップ | 初回起動時、その後約6時間ごと。サーバーごとに最新30件。管理操作荒らしを検知すると自動保存を一時停止 |
| 復旧 | 指定のバックアップにある削除済みロール・カテゴリ・テキスト・VCを再作成。ID対応表を保存して再実行時の重複を抑止 |
| 管理画面 | サーバー切替・権限確認・設定・履歴・ロック・復旧。スマホ対応。運用者1人の管理パスワードでログイン |

危険な権限は、管理者・サーバー管理・ロール管理・チャンネル管理・BAN・キック・Webhook管理・メンバーのタイムアウトです。
通常の管理作業でも閾値を超えると対象になります。管理者を無条件に除外しない設計です。大量の正当な作業を行う場合は所有者で行うか、保護を一時停止して、作業後に必ず戻してください。

## 1. Discord Botを作成

1. https://discord.com/developers/applications を開き、**New Application**で作成します。
2. **Bot**でトークンを発行します。これは初期設定時に自分のPCで入力します。
3. **Privileged Gateway Intents**の **SERVER MEMBERS INTENT** と **MESSAGE CONTENT INTENT** を有効にします。
4. **Installation / OAuth2 URL Generator**でスコープ **bot** と **applications.commands** を選び、次の権限を付けてサーバーに招待します。
   - View Channels / Send Messages / Read Message History
   - View Audit Log / Manage Messages / Moderate Members
   - Manage Roles / Manage Channels / Kick Members / Manage Webhooks
5. Discordのサーバー設定 → ロールで、**Guardのロールを保護対象の管理ロールより上**に移動します。

BotにAdministratorを付ける必要はありません。個別チャンネルの上書きでBotの閲覧・管理が拒否されている場合は、そのチャンネルでの対処に失敗するため、アクセスも確認してください。
広く公開するBotでは、Privileged Intentsの承認等が別途必要になる場合があります。

## 2. Windowsで起動

Python 3.12以上をインストールしてから、ZIPを展開し **start.bat** を開きます。

初回のみライブラリをインストールし、Botトークンの入力を求めます。入力文字は表示されません。
設定後に**管理パスワード**が表示されるので手元に保存してください。

起動コンソールに表示された次のURLを開きます。

**http://127.0.0.1:8787**

管理パスワードでログインし、サーバーを選びます。接続直後はサーバー一覧が空になる場合があるので、Discord接続後に「更新」を押してください。
**保護設定 → 通知先チャンネル**を管理者専用のチャンネルに設定してください。

コンソールを閉じるとBotも停止します。起動後は保護が有効になります。必ずテストサーバーで設定・ロール順位を確認してから本番へ導入してください。

手動起動は以下です。

```powershell
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe setup_guard.py
.venv\Scripts\python.exe server.py
```

Python 3.12環境で検証しています。音声を扱わないためPyNaClは不要です。

## 3. Linux / VPSで常時起動

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python setup_guard.py
.venv/bin/python server.py
```

systemdにする場合は `radius-guard.service.example` のユーザー名と絶対パスを実環境に合わせ、`/etc/systemd/system/radius-guard.service`に配置します。

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now radius-guard
sudo journalctl -u radius-guard -f
```

管理画面は初期状態ではVPS自身からだけ開けます。手元のWindowsでSSH転送すると、公開せずに管理できます。

```powershell
ssh -L 8787:127.0.0.1:8787 ユーザー名@VPSのIP
```

接続を維持したまま **http://127.0.0.1:8787** を開きます。

スマホ等からドメインで使う場合は、HTTPSのリバースプロキシを設置し、`.env`の `PUBLIC_ORIGIN=https://実際のドメイン` に変更して再起動します。プロキシはHostヘッダーを保持し、アプリの8787番ポートをインターネットに直接公開しないでください。プロキシが認識したOrigin/Hostと一致しないアクセスは拒否します。
管理画面はこのBotを動かしている運用者向けです。一般サーバー管理者へのセルフサービス公開・Discord OAuth認可はこの版にはありません。

Dockerを使う場合は `.env` を設定してから `docker compose up -d --build` でも起動できます。DBは名前付きボリュームに残ります。コンテナに含めるソースから`.env`・実DBは除外しています。

## Discord内のコマンド

| コマンド | 操作できる人 | 動作 |
| --- | --- | --- |
| `/guard` | サーバー管理者 | 保護状況を表示 |
| `/guard_lock` | サーバー所有者 | 緊急ロック |
| `/guard_unlock` | サーバー所有者 | 緊急ロック解除 |

設定・履歴・バックアップは管理サイトから操作します。コマンドは接続時に導入済みサーバーへ登録します。

## 復旧時の注意

- 元のメッセージ・ID・招待リンク・Webhook・Bot・スレッド・フォーラム・ステージ・ロールアイコン等は復元しません。お知らせチャンネルは通常テキストとして再作成します。
- 既存のチャンネル・ロールへの変更は上書きしません。削除された構成だけが対象です。ロールの元の順位は自動で戻さないので確認してください。
- 保存時のロール権限も復元します。正常な時点のバックアップを選んでください。復元ロールは誰にも自動再付与しません。BAN解除・剥奪ロールの再付与も本人確認後に手動で行ってください。
- 個別権限に必要なロール・メンバーが取得できないチャンネルは、意図しない公開を防ぐため再作成を保留します。履歴で確認してください。
- Botロールが下位にある・権限不足・Discord側のレート制限等では対処に失敗／遅延します。初回の削除を事前に阻止する方式ではありません。
- 所有者・Guard自身は自動対処対象外です。Bot以上のロール、管理対象外のmanagedロール等には制限があります。所有者が乗っ取られた場合を完全に封じ込めるものではありません。
- 連投・メンションの検知は人間のサーバー投稿が対象です。他Bot・Webhook・DM・古いキャッシュ外投稿の編集はこの検知の対象外です。既存の悪意あるWebhookはDiscordの連携設定で削除してください。
- 入室タイムアウトは新規入室者の閲覧や入室そのものを禁止するものではありません。入室前の検査やCAPTCHAは含みません。
- 緊急ロックは管理者・Webhook・外部アプリに効きません。新規作成チャンネルや対象外チャンネルは自動ロックされません。既にVCにいる人を強制退出させるものでもありません。
- 緊急ロックの解除は保存した上書き値に戻します。ロック中に同じ値を手作業で変更した場合には解除後の権限を確認してください。削除済みの対象があると復旧記録が残り、ロック中表示が残ることがあります。
- ロック中はBot自身の通知先権限にも影響し、通知が送れない場合があります。DBの履歴は保存されます。
- 検知の短期カウンターはメモリ上なので再起動でリセットされます。設定・履歴・バックアップ・ロック復旧情報はSQLiteに永続化します。

## 保存データと管理

`data/guard.db` にサーバー設定、ユーザーIDと処理履歴（サーバーごとに最新3,000件）、バックアップ、復旧対応表を保存します。投稿本文は保存しません。管理画面に表示する履歴は最新100件です。
`.env`にはBotトークンと管理パスワードが入ります。`.env`と`data/`は公開リポジトリに入れないでください。ZIPにはどちらも含まれていません。
管理パスワードを変更した場合は再起動してください。管理ログインは8時間で失効し、再起動時も全セッションを失効します。ブラウザにパスワード・トークンを保存しません。
履歴とバックアップを含むDBは、停止後にファイルをコピーして外部へバックアップできます。Dockerは停止してからボリュームを退避してください。

## 検証

```bash
python -m unittest discover -s tests -v
```

単体テストとHTTPテストで、検知閾値・混合管理操作・重複監査ログ・入室バースト・所有者保護・ロール剥奪・DB再読込・バックアップ世代保持・再復旧時の重複抑止・ロック解除・認証・CSRF・Host/Origin検証・ログイン回数制限を確認しています。
本物のDiscordサーバーでの実接続・操作は未検証です。実Botトークンを設定して、テストサーバーで以下を確認してください。

1. Botがオンラインになり、管理画面の権限確認が「取得済み」になる。
2. 専用テストアカウントで8秒以内に6件投稿し、タイムアウトと削除、履歴を確認する。
3. 所有者以外の専用管理アカウントで不要なテストチャンネル3個を削除し、その管理ロールの剥奪と自動保存の停止を確認する。
4. 保存済みバックアップから削除したテストチャンネルを再作成できるか確認する。
5. ロック→解除で通常メンバーの投稿権限が戻り、再起動後も設定が保持されるか確認する。
